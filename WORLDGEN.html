World Generation

Infinite streaming voxel world — Odin + SDL3 GPU compute raytracer

One-sentence model: the world is an infinite field defined by a pure function of coordinates. Worker threads materialise that function into voxel columns on demand, which the main thread uploads into a fixed-size toroidal GPU ring buffer centred on the player.

1. Spatial units

voxel
One cube. Smallest unit. Carries a Block_Type (21 kinds: terrain, ores, wood, leaves, water, torch).
chunk
8×8×8 voxels (CHUNK_VOXELS = 8). The unit of GPU upload.
column
All 16 stacked Y-chunks at one XZ position (CHUNKS_H = 16). The unit of generation work.
ring
64×16×64 chunks (CHUNKS_W = 64). The fixed GPU buffer the world wraps into.

2. The terrain function

Terrain is a pure function of world XZ (terrain.odin) — no state, no neighbours, fully deterministic. It returns a surface height and a biome; the column generator turns those into voxels.

height = SEA_LEVEL + continent_base(cont)      // ocean floor .. inland plains (cont per voxel)
       + hills * hill_amp                      // amplitude varies region to region
       + mountain * (55*mountain + ridged^2*150) // uplifted massifs with ridged peaks
then   badlands mesas (terraced in 8-voxel steps)
       rivers   (warped ridge-noise valleys, beds just below sea level)
       ravines  (narrow 30-55 deep cuts with near-vertical walls, high ground only)
       soft cap above y=180

Fields that vary over hundreds of voxels (temperature, moisture, hill amplitude, mountain/badlands/ravine masks, the river warp) are evaluated on a world-aligned 8-voxel lattice and bilinearly interpolated, so a column costs 9 lattice evaluations instead of 100. Columns, far tiles and single-point queries share the lattice, so they agree exactly.

Below the surface layers is stone with coal, iron and gold blobs (an integer hash per 4³ cell), carved by 3D cave noise between y = −64 and 110. terrain_at(wx, wz) / surface_height_at answer "where is the ground here?" without touching chunk data — used by trees, the far LOD, spawn search and cave darkness.

3. Trees: deterministic, per-column, self-clipping

Trees are the hard part — a single tree spans many chunks. The design that finally worked treats a tree as a pure function of its base position, regenerated independently by every column it overlaps, with each column keeping only the voxels that land inside it.

Why this is correct

  • Whether a tree grows at a spot, and which kind (oak, small oak, bush, spruce, cactus), comes from tree_at: a position hash against the biome's density.
  • A tree's RNG is seeded purely from its world XZ (wx*1000 + wz). Every column that regenerates it produces byte-identical geometry.
  • Tree_Target holds the 16 chunk pointers of one column plus its XZ origin. Every voxel write (set_voxel_world, place_leaves) is silently clipped: writes outside the column's 8×(16·8)×8 box are dropped.
  • A column scans every tree whose base falls within TREE_VOXEL_REACH = 48 voxels of its footprint. Trees straddling a boundary are drawn by both columns — each keeps its half — so edges are seamless with zero shared state and zero cross-thread writes.
column A column B ┌────────┐ ┌────────┐ │ 🌳─┼─┼─🌳 │ the tree is generated twice, │ /│ │ │ │\ │ once per column. A keeps the │ / │ │ │ │ \ │ left voxels, B keeps the right. └────────┘ └────────┘ identical RNG → seam is invisible

Why it is fast (the optimisation story)

Naively this is wasteful: a tree near a boundary is fully regenerated by ~6×6 columns. Three layers of AABB rejection make the wasted calls nearly free:

Whole treeaabb_hits_chunk on the tree's full bounding box, before any RNGTrees whose footprint misses this column entirely

The biggest single win was switching the work unit from a chunk to a column. The terrain noise sweep and the 97×97 tree scan depend only on XZ — doing them per-chunk repeated identical work 16× for every Y layer. Per-column, they run exactly once.

Measured: startup 6.05 s → 0.10 s. Tree-scan invocations 6615 → 441 (one per column). Terrain-noise time ~16× lower.

4. The streaming pipeline

enqueue_radius() main thread

Every frame, queue every XZ column within LOAD_RADIUS_XZ = 28 of the player that isn't already on the GPU. One job = one column.

↓

Worker_Pool 12 worker threads

Workers pop column jobs and call generate_column_at(wcx, wcz) — terrain + trees, fully isolated, no locks during generation. Lock-free in-flight counter tracks outstanding work.

↓

generate_column_at() pure

Allocates 16 chunks. One noise sweep for the surface map. Fills all 16 Y-chunks. One tree scan over the reach-padded footprint. Returns the column.

↓

integrate_ready_chunks() main thread

Drains finished columns. For each, integrates all 16 chunks into the ring (or frees the column if that XZ is already loaded — duplicate from re-enqueue).

↓

integrate_chunk() → GPU ring main thread

Computes the toroidal ring_slot. Evicts whatever chunk previously owned that slot. Copies voxels into gpu_voxels, tags the slot's owner, marks it dirty for upload.

5. The toroidal ring buffer

The GPU buffer is a fixed 64×16×64 grid. An infinite world maps into it by wrapping:

ring_slot(wcx, wcy, wcz):
    sx = ((wcx % 64) + 64) % 64      // wrap, handles negatives
    sz = ((wcz % 64) + 64) % 64
    return sx + wcy*64 + sz*64*16

As the player moves, far chunks and near chunks collide on the same slot. The owner tag (gpu_chunk_owner[slot] = (wcx, wcz)) records which world chunk currently lives there. When a new chunk claims a slot, the old owner is evicted from gpu_loaded and unqueued. The compute shader checks the owner tag before sampling, so a stale slot is never rendered as the wrong chunk.

This is why the world is "infinite" without unbounded memory: only a 64×64 chunk window around the player is ever resident. Walk far enough and coordinates wrap back onto the same physical slots, re-owned by new terrain.

6. Startup vs. steady state

Both use the exact same pipeline — there is no special-case loader.

Startup
Enqueue a small STARTUP_RADIUS_XZ = 10 radius and block (drain in a loop until worker_pool_idle) so the window opens to a populated world fast (~0.1 s).
Steady state
The game loop calls enqueue_radius(LOAD_RADIUS_XZ) + integrate_ready_chunks every frame. The ring fills out to full radius in the background while you play; columns crossing into range stream in continuously.

8. Key invariants

  • Determinism: terrain and trees are pure functions of world coordinates. Same coords → same voxels, always, on any thread.
  • No cross-column writes: a column only ever writes its own 16 chunks. Boundary trees are duplicated, never shared.
  • Atomic columns: a column is integrated all-16-chunks or not at all, so checking Y=0 in gpu_loaded is a valid "is this column present?" probe.
  • Owner-gated rendering: a ring slot is only valid if its owner tag matches the world chunk the shader expects.
